## 1. Вероятности из коэффициентов букмекера (эталон для сравнения)

Коэффициенты: o_H, o_D, o_A (`bet365_odds_home_win`, `bet365_odds_draw`, `bet365_odds_away_win`).

```
q_i      = 1 / o_i                      для i = H, D, A   ("сырая" вероятность)
S        = q_H + q_D + q_A              (всегда > 1)
margin   = S - 1                        (маржа букмекера, обычно 2-6%)
p_i      = q_i / S                      (нормализованная вероятность, сумма = 1)
```

Пример (первая строка файла, Burnley - Swansea, коэффициенты 2.40 / 3.30 / 3.25):

```
q = 0.4167 ; 0.3030 ; 0.3077      S = 1.0274      margin = 2.74%
p = 0.4056 ; 0.2950 ; 0.2995      (сумма = 1.0000)
```

Опционально (улучшение): метод степени, он лучше учитывает, что фавориты и аутсайдеры
в коэффициентах искажены по-разному:

```
p_i = q_i ^ c / sum_j (q_j ^ c)         c >= 1 подбирается так, чтобы sum p_i = 1
```

Для проекта достаточно простой нормализации (первая версия). Метод степени можно
добавить как вторую "версию букмекера" и сравнить.

### Метрики для сравнения моделей с букмекером

```
Log loss = -(1/N) * sum_n  ln( p_n[y_n] )            p_n[y_n] = вероятность, данная реальному исходу
Brier    =  (1/N) * sum_n  sum_k ( p_n[k] - 1{y_n = k} )^2     k = H, D, A
Accuracy =  доля матчей, где argmax(p) совпал с результатом
```

Ориентиры: случайная модель "1/3 на каждый исход" даёт log loss = ln 3 = 1.0986.
Наивная линия "всегда победа хозяев": accuracy около 45% (1696 из 3800).
Главная метрика - log loss (оценивает качество самих вероятностей, а не только угаданный исход).

### Проверка "ценности" (по желанию, для симуляции ставок)

```
EV = p_model * o - 1          ставим, если EV > порога (например 0.05)
```

## 2. Рейтинг Elo (несколько вариантов для сравнения)

### Базовая формула

```
E_H = 1 / (1 + 10 ^ ( -(R_H + h - R_A) / 400 ))       ожидаемый результат хозяев (0..1)
E_A = 1 - E_H

S_H = 1 (победа хозяев), 0.5 (ничья), 0 (поражение)   S_A = 1 - S_H

R_H' = R_H + K * G * (S_H - E_H)
R_A' = R_A - K * G * (S_H - E_H)
```

R - рейтинг (старт 1500), K - скорость обучения, h - бонус домашнего поля
(в очках Elo), G - множитель разницы голов (в базовой версии G = 1).

Пример: R_H = R_A = 1500, h = 65, K = 20. Тогда E_H = 0.5925. Если хозяева проиграли
(S_H = 0), рейтинг хозяев падает на 20 * 0.5925 = 11.85, гостей растёт на столько же.

**Главное правило против утечки данных:** для матча в признак идёт рейтинг **до** матча,
и только после этого рейтинг обновляется результатом.

### Варианты, которые стоит сравнить

| Вариант | Идея | Параметры |
|---|---|---|
| A. Базовый | без домашнего преимущества | K = 20, h = 0 |
| B. С домашним полем | как A, но хозяевам добавляется h | K = 20, h = 65 (подобрать 0-100) |
| C. С разницей голов | победа с большим счётом двигает рейтинг сильнее | G ниже |
| D. Быстрый / медленный | разные K | K = 10, 20, 40 |
| E. Раздельные рейтинги | у каждой команды два рейтинга: дома и в гостях | R_home обновляется только в домашних матчах, R_away только в гостевых |

Множитель разницы голов (вариант C), N = |голы хозяев - голы гостей|:

```
G = 1                 если N <= 1
G = 1.5               если N = 2
G = (11 + N) / 8      если N >= 3
```

Переход между сезонами (улучшение для всех вариантов): возврат к среднему.

```
R_new = (1 - a) * R_old + a * 1500          a = 0.25 (подобрать 0.1-0.4)
```

Новички (команды, вышедшие из Championship), у которых нет рейтинга: старт 1450-1500.

### Как превратить Elo в вероятности трёх исходов

Формула Elo даёт один "ожидаемый результат", а нам нужны три вероятности (H, D, A).
Самый простой путь - сделать это прямо в проекте: взять разницу рейтингов как признак
и отдать логистической регрессии.

```
elo_diff = R_H + h - R_A        (признак)
вероятности (H, D, A) = логистическая регрессия(elo_diff, форма, ...)
```

Это естественно связывает Elo с темой курса и не требует отдельной формулы для ничьей.

### Как выбирать параметры (K, h, a)

1. Разделить данные по времени: обучение 2016/17 - 2022/23, валидация 2023/24, тест 2024/25 - 2025/26.
2. Первый сезон считать "разогревом" (рейтинги ещё не устоялись), в оценку не брать.
3. Перебирать K, h, a сеткой и выбирать значения с лучшим log loss **на обучении/валидации**.
4. Тестовые сезоны трогать один раз, в самом конце.

### Дополнительные признаки формы (для сравнения с Elo)

```
form_X(k) = среднее значение X за последние k матчей команды ДО текущего матча   (k = 5)
```

X: забитые и пропущенные голы, очки (3 / 1 / 0), удары в створ.
Реализация в pandas: считать по команде, сортировать по дате и применять `shift(1)` перед
скользящим средним, иначе текущий матч попадёт в собственный признак.

## 3. Как сделать кластеризацию эффективнее

Проблема "в лоб": профиль команды за весь сезон считается по всем 38 матчам, включая те,
что ещё не сыграны на момент прогноза. Если использовать такой кластер как признак для матчей
того же сезона, получится утечка будущего.

### Рекомендуемая схема

**1. Что кластеризуем.** Не "команду за сезон", а снимок команды перед матчем:
профиль за последние 10 матчей. Тогда точек порядка 7600 (две команды на матч) вместо 200,
кластеры стабильнее, и утечки нет.

**2. Признаки профиля (в расчёте на один матч, не суммы):**

```
голы забитые, голы пропущенные, удары, удары пропущенные,
удары в створ, удары в створ пропущенные, угловые, жёлтые карточки, красные карточки,
доля ничьих
```

Не включать очки и победы: цель кластеризации - стиль игры, а не результат.

**3. Подготовка:**
- стандартизация (`StandardScaler`), иначе голы и удары несопоставимы по масштабу;
- удалить сильно скоррелированные признаки (удары и удары в створ), либо сжать через PCA
  до 3-4 компонент (около 85-90% дисперсии). Кластеры будут чище, и график получится наглядным.

**4. Выбор числа кластеров k (перебор k = 2...8):**
- метод локтя (inertia);
- коэффициент силуэта (silhouette): чем выше, тем лучше;
- устойчивость: запустить с разными random_state, сравнить разбиения (Adjusted Rand Index);
- `n_init = 20-50`, фиксированный `random_state`.
Практически выбирают k = 3-5, чтобы кластеры можно было назвать словами.

**5. Сравнить алгоритмы (даёт баллы за глубину):**

| Метод | Плюс |
|---|---|
| K-means | простой, объясняется быстро |
| Gaussian Mixture | даёт **вероятность принадлежности** к кластеру: мягкие признаки лучше жёстких меток |
| Иерархическая (Ward) | дендрограмма хорошо смотрится в презентации |

**6. Без утечки:** обучить кластеризацию (скейлер + модель) **только на обучающих сезонах**,
а для валидации и теста лишь применять `predict` / `transform`.

**7. Как использовать в моделях:**
- признаки: one-hot метки кластера хозяев и гостей, либо вероятности GMM;
- пара кластеров (кластер хозяев x кластер гостей) - при k <= 4 это максимум 16 пар;
- обязательный эксперимент: логистическая регрессия **с** кластерами и **без** них,
  сравнить log loss на валидации.

**8. Что показать (графики):**
- проекция PCA в 2D, раскрашенная кластерами;
- таблица центров кластеров в исходных единицах, с названиями ("атакующие", "оборонительные", ...);
- тепловая карта: доля побед хозяев для каждой пары кластеров (хозяева x гости).

**Честная оговорка для отчёта:** прирост от кластеров, скорее всего, будет небольшим,
потому что Elo и форма уже содержат часть той же информации. Это нормальный результат:
в отчёте достаточно показать сравнение "с кластерами / без" и объяснить причину.
